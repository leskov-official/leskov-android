# LESKOV Android 3.2 — исправления по тестированию на Samsung

## Что изменено в исходниках

1. WebView: на малых экранах интерфейс сайта уменьшен с помощью адаптивного CSS и корректной настройки viewport/масштабирования. ТекстZoom=90%; все страницы, формы и всплывающие окна требуют проверки на устройстве. Пользователь может вручную изменять масштаб жестом.
2. Убрана дублирующая нативная **мини-панель** над нижней навигацией. Основной видимый плеер — оригинальный плеер сайта. Media3 остаётся сервисом для переноса поддерживаемого HTTPS-трека в фон и управления с заблокированного экрана. Полная синхронизация индикаторов плеера сайта с Media3 при смене PHP-документа требует согласованного серверного API: не объявлять этот сценарий полностью решённым без тестирования.
3. Передача данных трека: из сайта считываются название, исполнитель и первая подходящая обложка из Media Session или DOM. Только HTTPS-обложки с домена lesv.online передаются нативным сервисам. Legacy WebView-уведомление использует Android MediaSession/MediaStyle для экрана блокировки и безопасно скачивает обложку с ограничениями размера и времени. На системах Android 13+ оформление уведомления выбирается самой ОС.
4. Нижняя навигация: подписи компактнее, «Профиль» не должен обрезаться при обычном системном масштабе шрифта.
5. Иконки установки и splash: оригинальный знак LESKOV уменьшен на белом фоне, при этом сам рисунок не изменён.
6. Веб-страницы настроек Push: кнопка «Включить Push» направляется в безопасный нативный мост, уведомление об отсутствии browser Push уточнено. **Реальные FCM пока невозможны без Firebase-конфигурации и серверной доставки**.
7. Robolectric тест: исправлено ошибочное ожидание повторной загрузки уже открытой Главной. Тесты должны запускаться с JDK 21 для API 36.
8. GitHub Actions: SDK action v4; JDK21; lint выполняется даже при ошибке тестов.

## Нужные действия на PHP-сайте

Архив LESKOV_SERVER_CALLS_PATCH.py отдельно. Анализ старого архивного кода показал, что `feed.php`, `search.php`, `discover.php`, `notifications.php` не подключают существующий `app_calls_global_html()`/`cms_calls_assets()`. Скрипт добавляет существующий серверный компонент только авторизованным пользователям. Он НЕ запускается сам и НЕ заменяет проверки на актуальном серверном коде. Запускать сперва в staging, с резервной копией, после чего проверять настоящие входящие вызовы с другого аккаунта.

## Тестирование сборки

Для GitHub: распаковать PATCH поверх содержимого текущего `~/Projects/leskov-android`, выполнить `git add -A && git commit && git push`. В `Actions` проверить `assembleDebug`, `testDebugUnitTest`, `lintDebug` и скачать новый `LESKOV-Android-debug-APK`.

**Важно:** APK из новой CI-сборки может иметь другую debug-подпись. Если Android откажется обновить старую тестовую установку, удалите старую версию перед установкой новой (локальные данные APK будут удалены; серверные данные аккаунта сохраняются).

Ни одно изменение не проверено здесь запуском на Android: статическая проверка не заменяет сборку и реальные тесты. Версия готова **к повторной сборке и испытаниям**, не к публикации в Google Play.
