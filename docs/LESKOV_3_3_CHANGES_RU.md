# LESKOV Android 3.3 — исправления по Samsung

Это патч к GitHub `leskov-official/leskov-android` поверх успешной сборки #5 (commit `4c9bd31`).

## Изменения, выполненные в Android-коде

1. Встроенный сайт: удалено глобальное CSS `html { zoom: .82 }`, которое ломало координаты окна, фиксированные слои и адаптивную ширину. Сохранён стандартный textZoom=100%. Уменьшены большие H1/H2/H3 и ограничена ширина медиа и форм; модальные окна настроек уведомлений ограничены по высоте и получают собственную прокрутку. Это нельзя считать проверенным без повторных снимков экрана на телефоне.
2. Нативные окна для гостя (Лента, Чаты, Профиль): уменьшены отступы, логотип, высота кнопок и максимальная ширина карточки.
3. Адаптивная иконка: тёмный фон заменён на белый, чтобы он не выглядывал чёрными полосками справа и слева от квадратного оригинального изображения. Оригинальная графика LESKOV не заменена. Установщик и домашний экран по-прежнему используют правила масок Samsung; SplashScreen — отдельный ресурс.
4. Встроенный WebView: добавлен `onRenderProcessGone` с пересозданием Activity. Это обработка *одного класса* сбоев Chromium. Если процесс приложения падает по другой причине, нужен `FATAL EXCEPTION` с телефона; см. `tools/CAPTURE_ANDROID_CRASH_RU.sh`.
5. Аудио из веб-плеера: в Android MediaSession передаются позиция, длительность, признаки существования кнопок «Следующий/Предыдущий». Android может отрисовать прогресс/перемотку; стрелки предусмотрены **только при обнаружении рабочей функции управления на сайте**. Обложки декодируются с ограничением памяти. Android 13+ сам определяет вид карточки в панели/на экране блокировки.
6. После перехода на следующую PHP-страницу Android отправляет событие `leskov:native-playback` и, если найден существующий веб-плеер, добавляет внутрь него компактную кнопку управления текущим нативным воспроизведением — без второго плеера над нижней навигацией. Серверный UI должен слушать это событие для полной синхронизации собственного playlist/progress; contract below.
7. Состояние URL нижней навигации фиксируется после фактической загрузки страницы, а не при нажатии. Добавлен тест, подтверждающий прямой переход авторизованного пользователя на `feed.php`, но если PHP-сервер отвечает редиректом на `profile.php`, его нельзя устранить исключительно в Android. Проблемный redirect фиксируется логом `LeskovNavigation`.
8. Версия APK поднята до `3.3.0` / versionCode 6.

## Ограничения и неподтверждённое

- **Реальная причина вылета Samsung ещё не определена.** Обработаны возможные причины (renderer death, большие bitmap, отказ запуска foreground service), но для полного исправления нужен Logcat.
- **Переход Лента → Профиль**: Android-код выбирает `feed.php`. Если сам сервер возвращает `302 Location: profile.php` или перенаправляет JavaScript, понадобится серверная правка. Проверь журнал `LeskovNavigation`.
- **Полная синхронизация сайта с Media3**: Android публикует событие, но веб-плеер сайта должен поддерживать его (и обратные команды) на серверной стороне. Не объявлять проблему закрытой до end-to-end теста.
- **Prev/Next внутри Media3**: при наличии только одного выбранного потока у нативной очереди нет следующих треков. Для полноценной очереди потребуется передавать серверный авторизованный playlist, не обходя Premium.
- **Нативные FCM push**: Firebase и серверный endpoint ещё должны быть настроены отдельно. Медиаплеер в системном уведомлении не заменяет FCM.
- Эти изменения прошли только статическую проверку, **не Gradle и не Samsung-тестирование**. После push проверить `assembleDebug`, `testDebugUnitTest`, `lintDebug` и скачать новый APK.

## Медиасобытие на стороне сайта

Сайт может подписаться на событие:

```javascript
window.addEventListener('leskov:native-playback', function (event) {
  const {active, playing, title, artist} = event.detail;
  // Показать в оригинальном UI, что поток сейчас управляется Android Media3;
  // обновлять Play/Pause и текущий трек без повторного запуска HTML <audio>.
});
```

Этот обработчик — пример контракта, **он ещё не установлен на `lesv.online`**. Не нужно проигрывать один и тот же поток одновременно в WebView и Media3.
