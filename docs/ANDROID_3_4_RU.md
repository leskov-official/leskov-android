# LESKOV Android 3.4.0

## Масштаб и интерфейс

- Убрано автоматическое уменьшение desktop-страницы WebView. Viewport использует ширину устройства, начальный масштаб 1 и сохраняет pinch-to-zoom.
- Размер веб-текста учитывает системный fontScale Android в диапазоне 75–200% и обновляется при изменении конфигурации.
- Единый CSS приложения: адаптивные контейнеры, перенос длинных названий, доступный фокус, поля от 48 CSS px, кнопки плеера от 44 CSS px, ограничение модальных окон высотой экрана. Без zoom/transform корневой страницы и без замены движка сайта.
- Тема получила единые скругления и более читаемые основной текст и подписи. Навигация адаптирует ширину к системному шрифту, показывает выбранный пункт прокруткой и ограничивает ширину на планшете.
- Меню «Ещё» прокручивается, содержит фирменную карточку с версией, отдельные области иконок и анимированное нажатие. Экран ошибки ограничен по ширине, кнопки входа/повтора растут по высоте, ссылки документов делят доступную ширину.
- Поля формы защищены IME-inset, навигация скрывается при клавиатуре. Системные иконки светлые на тёмном интерфейсе.
- Веб-анимации учитывают prefers-reduced-motion. Убран постоянный пульс экрана ошибки. Сохранены переходы экранов, отклик навигации и кнопок.
- Гостевые реакции больше не блокируются Android-инъекцией: авторизацию обрабатывает сам сайт.

## Premium-плеер сайта

`leskov-player-bridge.js` использует `window.__leskovPlayerManager.active`, `instances`, отдельный header Premium engine (`__leskovHeaderPlayerAudio`, `[data-header-player]`), события `leskov:player:*` и реальный `media` плеера. Поддерживает аудио вне DOM и плееры, добавленные после загрузки страницы. При поддержке WebView скрипт устанавливается до скриптов страницы, иначе при commit/finish.

Название, исполнитель, обложка, позиция, длительность и возможность смены трека передаются в Android. Для отдельной панели в шапке метаданные и очередь читаются из её текущего состояния, а кнопки сайта сохраняют собственную логику паузы и режимов. При паузе сохраняются сведения о выбранной композиции. Команды Android направляются тому же экземпляру плеера через play/pause/seek/next/prev; произвольный первый audio страницы больше не используется для управления.

Ringtone, notification sound, WebRTC srcObject, видео и чужие источники не считаются музыкой. Blob-аудио контролируется внутри WebView, но не передаётся Media3.

При переходе между документами или выходе из приложения Media3 получает текущий HTTPS-трек и позицию. Если сайт уже предоставил валидный плейлист до 100 треков и его текущая запись совпадает с реально играющим URL, передаются также очередь и режим sequential/shuffle/repeat. Проверяется HTTPS-источник lesv.online, используются cookies веб-сессии; сервер продолжает проверять доступ к каждому потоку. При несовместимой очереди передаётся только текущий трек. Смена трека Media3 обновляет сведения, доступные веб-странице. Тайм-аут передачи не позволяет зависшему JS заблокировать навигацию.

На экране остаётся плеер сайта. После передачи воспроизведения в Media3 управление текущим треком доступно внутри него и через системные медиакнопки. Элементы сайта, появившиеся с задержкой, получают актуальный статус. Очередь/режим, изменённые на сайте уже после передачи, автоматически в Media3 не переносятся: новое воспроизведение сайта возвращает управление WebView.

Проверены и основной класс, и отдельный Premium-плеер в шапке. Это проверка совместимости движков, а не Premium-авторизации.

Повтор браузерных проверок (Playwright устанавливается вне проекта):

```bash
npm install --prefix /tmp/leskov-browser-check playwright --no-audit --no-fund
NODE_PATH=/tmp/leskov-browser-check/node_modules node tools/check_mobile_layout.cjs
NODE_PATH=/tmp/leskov-browser-check/node_modules node tools/check_premium_player.cjs
```

Путь к Chromium можно задать через LESKOV_BROWSER. Отчёты и скриншоты масштаба сохраняются в `build/reports/mobile-layout/`. Браузерный тест использует текущую версию сайта и может выявить несовместимость при его обновлении.

GitHub Actions выполняет сборку debug APK, Robolectric, lint и оба офлайн-теста аудио. Локальная среда не содержит Java/Android SDK.

## Приёмка на устройстве

Нужны вход в реальный Premium-аккаунт и проверка на Android: разрешённый поток, закрытие/открытие плеера, shuffle/repeat, следующий трек после блокировки, управление гарнитурой, переходы между страницами, восстановление сети и истечение сессии. Также нужны проверки нативных экранов при шрифте 200%, TalkBack, жестовой навигации, альбомной ориентации и клавиатуре. Эти сценарии не заменяются браузерным стендом; публикация в магазине не выполнялась.
