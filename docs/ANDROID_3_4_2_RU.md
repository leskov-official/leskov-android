# Android 3.4.2

Изменения по скриншотам IMG_6343–IMG_6353:

1. Push: разворачиваемый текст, категории, фирменный логотип с безопасными отступами; нажатие открывает внутреннюю страницу, включая запуск из закрытого приложения.
2. Профиль, лента и поиск: ограничение ширины контейнеров, перенос метаданных, компактный поиск без выхода за экран.
3. Компактные фирменные сообщения приложения. Центр уведомлений получает подтверждённое состояние регистрации Firebase и разрешений Android; включённая кнопка открывает системные настройки. Возврат из настроек обновляет статус.
4. Скрыта полоса прокрутки стикеров, прокрутка сохранена.
5. Три режима Premium-плеера расположены в одном компактном ряду.
6. В диалогах прокручивается история или список; шапка и форма отправки остаются видимыми.
7–8. Уменьшены карточка гостя и пункты «Ещё», ограничено разрастание их шрифта.
9–11. Исправлены значок уведомления, размер логотипа уведомлений и пропорции логотипа шапки сайта. Обложка трека остаётся в метаданных медиа для экрана блокировки.
12. Лайк и добавление трека используют защищённый JSON endpoint mobile_tracks.php. Интерфейс меняется после подтверждения сервера, очередь Premium обновляется без смены текущего аудио. Сохраняются Premium-проверка, CSRF, проверка доступности трека и ограничение частоты.

Серверные файлы backend/mobile_tracks.php, mobile_push.php, includes/mobile_push.php и notification-target-url.patch применены на lesv.online. Ключ Firebase не менялся и в репозитории отсутствует. Резервные копии серверных файлов сохранены вне сайта.

Проверки: tools/test_app_shell.js; tools/test_player_bridge.js; tools/validate_source.py; PHP lint; tools/test_mobile_backend.py (авторизация, CSRF, Premium, доступность трека, успешные операции); браузерные fixtures tools/check_3_4_2.cjs (320/360/412 px, включая диалоги и сохранение прокрутки). Нативные проверки NotificationPresentationTest и CompactChromeTest выполняются в CI вместе со сборкой и Android lint.

Системный запрос разрешения Android и оформление системной панели контролирует ОС. Фирменное оформление применяется к сообщениям приложения и содержимому уведомлений. Проверка реального телефона после установки APK необходима; браузерные fixtures не заменяют её.
